# Building Inker: a SaaS for tattoo artists, end to end

What Inker is today and how it is built. I founded it in February 2025 and I still build and operate all of it.

## The problem

Most tattoo artists in Brazil run their business in WhatsApp. A client sends a reference, the artist replies with a price, then they agree on a date and a deposit. All of that happens by hand, in chat, between sessions.

Inker gives the artist one place for quotes, agenda, clients and payments. It starts from WhatsApp, because that is where the work already is.

Today Inker has 800 users, and they have processed more than 3,000 quotes.

## Three codebases

- **App:** React Native with Expo, on iOS and Android.
- **Web:** Next.js, for the public pages and the logged-in product.
- **API:** NestJS, with PostgreSQL, and Redis with BullMQ for background jobs.

The app talks only to the API. Every feature has one contract document, and the API change lands first.

## Kitsune, the studio assistant

Kitsune is the AI agent inside Inker. It runs in production on the Vercel AI SDK, with OpenAI as the main provider and Gemini and Anthropic as fallbacks.

It uses tools to work across the studio:

- a daily queue of what needs attention,
- action cards, where the artist approves an action before it runs,
- drafts of quote replies,
- lead scoring from the real chat history,
- a daily summary.

It also turns a reference photo into a stencil, with Gemini image models. That works in the app, in the chat and in the quote flow.

## WhatsApp

Inker has a multi-tenant WhatsApp Cloud API inbox, with embedded signup, lead scoring and background jobs.

Around it there are workflows that start in WhatsApp: importing a chat export, Pix deposits, session reminders through approved templates, and follow-ups for requests that went quiet.

## Billing across three stores

An artist can subscribe on the web with Stripe, in the iOS app with Apple in-app purchase, or in the Android app with Google Play.

All three sit behind a single entitlements API, so the rest of the product asks one question: what can this account do?

On the Stripe side, webhooks went through a shadow mode first, and payment events go through a durable outbox, so an event is not lost and is not sent twice.

## Native iOS inside Expo

The app has home-screen widgets on iOS and Android, a Siri shortcut and a Live Activity on the lock screen. The iOS parts are written in Swift, and the app is still a managed Expo project.

## Infrastructure

Production moved from Railway to AWS: EC2, S3 and CodeBuild, with a deploy on every push.

Incidents and failed cron jobs send an alert to Discord. I wrote about the idea in [Sending logs to Discord with webhooks](/blog/discord).

## Keeping quality with one person

The API validates input with Zod, has rate limiting and an OpenAPI contract, and uses strict TypeScript.

CI enforces the architecture. Two ratchets stop import cycles and file sizes from growing, and the integrated suite had 3,259 tests in September 2026.

## Growth

I also built the funnel: signup attribution, PostHog and Meta Conversions API events, a referral program, and an onboarding that starts from the artist's Instagram handle.

## Running it with agents

I build and operate Inker mostly with coding agents. That only works with tools that let an agent act, stop, ask and show what happened.

Those tools became five open-source projects. One of them is the approval flow in [Human approval for AI agents](/blog/approval-links).

## What it taught me

I own the product decisions, the code, the marketing posts, the support tickets and the conversations with users about what to build next.

Inker taught me to treat engineering as one part of making a product work for real people and for the business.
