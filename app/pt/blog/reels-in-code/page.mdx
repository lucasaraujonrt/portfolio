## O que é código e o que não é

Quero ser exato aqui, porque "vídeo feito em código" pode soar maior do que é.

- **Código:** layout, tipografia, toda animação, a linha do tempo e onde cada som toca.
- **Gravado:** as cenas do app. É o app de verdade rodando no simulador do iOS, com dados de demonstração.
- **Gerado:** a voz é texto convertido em fala, e a música é uma faixa gerada.
- **Sintetizado:** os seis efeitos sonoros. São arquivos mono curtos, de 60 a 500 ms, sem biblioteca de samples.

Então o código não substitui a gravação. Ele substitui o editor de vídeo.

## Por que não um editor de vídeo

O primeiro rascunho foi um corte simples com ffmpeg: clipes, legendas, música. Foi reprovado por não parecer com o nosso produto.

A versão 2 ganhou movimento. A versão 3 ganhou um som pequeno para cada ação. Essa foi aprovada e virou o modelo de todo vídeo novo.

Cada rodada foi uma mudança no código e um render novo. Ninguém arrastou clipe em linha do tempo.

## A narração manda no tempo

O reel tem cinco trechos (no código, "beats"). Cada um tem uma frase de narração.

Duração fixa por trecho não funciona: frase curta deixa silêncio sobrando, e frase longa fica cortada. Então a duração de cada trecho vem dos arquivos de áudio:

```tsx
// Narration lengths (s) after trim + atempo 1.08.
// A beat lasts the line + a breath, never under MIN.
const NARR = [1.56, 2.75, 2.7, 2.48, 3.2]
const MIN = [2.4, 4.4, 3.3, 3.4, 3.6]

const B = NARR.reduce<number[]>(
  (acc, d, i) => {
    const beat = Math.max(s(d) + 16, s(MIN[i]))
    const tail = i === NARR.length - 1 ? 24 : 0
    return [...acc, acc[i] + beat + tail]
  },
  [0],
)

export const RW_DURATION = B[NARR.length]
```

`s()` converte segundos em frames. `B` guarda o frame em que cada trecho começa, e o último valor é a duração do vídeo inteiro.

Quando uma frase da narração muda, eu mudo um número. Todos os trechos seguintes se deslocam, junto com tudo o que está dentro deles.

## Um trecho é um componente

Cada trecho é um componente React que só conhece o próprio frame local. A raiz coloca um depois do outro:

```tsx
const BEATS = [B1, B2, B3, B4, B5]
// The outgoing beat fades over the first frames of the next one,
// so a cut never dips to an empty frame.
const OVERLAP = 7

{
  BEATS.map((_, i) => {
    const last = i === BEATS.length - 1
    const length = B[i + 1] - B[i] + (last ? 0 : OVERLAP)
    return (
      <Sequence key={i} from={B[i]} durationInFrames={length}>
        <Beat i={i} />
      </Sequence>
    )
  })
}
```

Dentro de um `Sequence`, o frame 0 é o começo daquele trecho. Então um trecho diz "a narração começa no frame 6", e isso continua valendo onde quer que o trecho caia.

A sobreposição de 7 frames existe por causa dos cortes. Sem ela, um corte pode passar por um frame que mostra só o fundo.

## Um vocabulário pequeno de movimento

Todo movimento usa as mesmas poucas funções:

```ts
export const ENTER = 12
export const EXIT = 7
export const STAGGER = 2

/** 0→1 entering at `at`. */
export const inP = (f: number, at: number, dur = ENTER) =>
  interpolate(f, [at, at + dur], [0, 1], { ...clamp, easing: EASE_OUT })

/** 1→0 leaving at `at`. */
export const outP = (f: number, at: number, dur = EXIT) =>
  interpolate(f, [at, at + dur], [1, 0], { ...clamp, easing: EASE_OUT })
```

As regras são curtas:

- As coisas entram em 12 frames e saem em 7. Sair é mais rápido que entrar.
- Tudo é um fade com um deslocamento curto. Não tem mola nem quique.
- Itens de um grupo começam com 2 frames de diferença.

Com um vocabulário só, um trecho novo fica parecido com os outros sem ninguém precisar ajustar.

## Impacto: um anel, faíscas e uma tremida

Quando a mascote cola um widget na tela inicial, três coisas acontecem no mesmo frame: um anel cresce a partir do espaço do widget, faíscas pixeladas saem pelas bordas e o celular treme.

A tremida é uma expressão só:

```tsx
// Phone shake on impact.
const d = f - FLY.slam
const shake = d >= 0 && d < 10 ? Math.sin(d * 2.6) * (10 - d) * 1.2 : 0
```

É uma onda senoidal que some em 10 frames. O valor entra num `translate` aplicado ao celular.

## Som posicionado por frame

Os efeitos sonoros são a parte que as pessoas menos notam e mais sentem. Cada um é um componente com um número de frame:

```tsx
/** Micro sound effect (synthesized in public/reel-widgets/sfx). */
type SfxProps = { at: number; name: string; vol?: number }

const Sfx: React.FC<SfxProps> = ({ at, name, vol = 0.5 }) => (
  <Sequence from={Math.max(0, at)} layout="none">
    <Audio src={A(`sfx/${name}.wav`)} volume={vol} />
  </Sequence>
)
```

O reel usa esse componente 16 vezes, com seis sons: clique, toque, pop, whoosh, moeda e brilho.

O som fica ao lado da animação a que ele pertence, com o mesmo número de frame. Se eu movo a animação, movo o som na mesma linha do diff.

## Área segura faz parte do layout

O Instagram desenha a própria interface por cima do reel. Num quadro de 1080×1920 a gente não deixa nada importante:

- nos 220 px do topo, onde ficam as abas;
- nos 420 px de baixo, onde ficam a legenda e os botões;
- nos 120 px da direita, onde ficam os botões de ação.

A gente aprendeu isso com um reel em que um rótulo ficou embaixo das abas. Agora os frames são conferidos com essas margens antes do render.

## O que eu manteria

- Deixe o áudio definir a linha do tempo. Não encaixe o áudio numa grade fixa.
- Faça de cada trecho um componente com o próprio frame local.
- Mantenha o vocabulário de movimento pequeno e reutilize.
- Coloque cada som ao lado da animação a que ele pertence.
